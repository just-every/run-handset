# Prompt media boundaries

The native greeting editor creates preparatory drafts. A new draft never changes approved audio or a published flow. Greeting-only members may upload or record local audio for their selected prompts; synthesis, phone requests, exact approval and publication retain their separate owner authority.

| Flow | Fields and destination | Purpose and current permission | Storage, retention and erasure boundary |
| --- | --- | --- | --- |
| Local upload and browser recording | WAV bytes, language, schedule variant and exact prompt to this installation | Explicit native author action; exact greeting scope and current native authority rechecked at save | Normalized audio and metadata in installation D1. Configured US location, complete retention and portable erasure composition remain unqualified under HND-027, HND-065 and HND-066. |
| Typed text to speech | Model, typed script, voice, style and WAV format to the configured direct HTTPS AI destination | Current native owner and enabled installation AI configuration; no customer recording or live stream is supplied by this door | A preparatory draft is stored locally. The configured provider's actual US processing, retention and erasure have not been qualified. A configured HTTPS address is not proof of an approved model or region. |
| Requested phone greeting | Provider account, recording identity and exact call metadata, then WAV bytes from the fixed Twilio API host | A signed, account-bound and call-bound callback, one-time PIN and current source consent; exact requesting owner's native version and registered extension checked before metadata, before media retrieval and before save | The PIN is hashed. Normalized draft audio and attributed request history remain in installation D1. No callback is dialed by this server. Real carrier recording, provider retention and physical receipt remain unqualified. Earlier pending requests without an author-version approval require a fresh request. |
| Incoming MMS reference | Signed provider account and message fields, MIME and an HTTPS media reference on the exact Twilio host and standard port | Current selected source and verified carrier signature | Metadata only; this path fetches no MMS bytes. Capture, playback and export remain separate authority. |

Private mutations require this installation's origin. Provider callbacks require their defined signature instead of a browser session. Native inputs and signed callback bodies are bounded while reading. Provider audio reads are bounded by declared and actual byte counts, require WAV media type, and do not follow redirects. WAV parsing rejects inconsistent RIFF and chunk lengths, incomplete sample frames, inconsistent byte rate and alignment, duplicate format or data chunks and invalid size or duration. Odd-length output includes the container pad byte.

No arbitrary callback media URL is fetched. Source consent and current author authority are checked again before a phone media GET and after its bounded read. Withdrawing authority during metadata readback prevents the media request itself. Provider error bodies do not become UI notices, stored prompt values or audit content.

Public-door proof is in `tests/handset-prompts.mjs`, “Uploaded, browser-recorded, phone-recorded and Spanish speech prompts are refused, previewed, approved, pinned and kept through rollback”, extended by `tests/helpers/handset-prompt-security.mjs`. It rejects malformed uploads and wrong-origin JSON and form mutations; refuses hostile provider redirects, bad MIME and oversized declared or streamed responses; asserts no new draft or request to a redirect destination; inspects populated runtime logs, responses, prompt storage and the ordinary audit export for planted synthetic credentials; and withdraws source authority during metadata readback. The MMS cases assert both refused destinations and accepted metadata without media retrieval. The existing prompt console journeys show the malformed-file refusal at 1440 and 390.

This proves application and substituted network-edge behavior. It does not prove encrypted credential custody, actual carrier or SIP credential rotation during calls, TLS or SRTP qualification, consent-filtered model audio, paused-interval exclusion, all external connector declarations, approved US regions, recording archive scrubbing or absence of credentials and executable authority from a portable installation archive. HND-048 remains PARTIAL with those original requirements retained.
